# Мир Гольфа — мобильный стартовый проект

Это стартовый прототип мобильного приложения «Мир Гольфа» для календаря турниров по гольфу в России и СНГ.
Включает:
- Expo / React Native интерфейс с вкладками «Турниры», «Аналитика», «Источники».
- Демонстрационные карточки турниров с датами, статусом, уровнем и ссылкой на первоисточник.
- API-заготовку на FastAPI.
- Схему данных PostgreSQL.
- План ежедневного сбора и контроля качества.

## Важно
Это **работающий UI-прототип с демонстрационными данными**, а не уже размещённый в магазинах продукт. Автоматический сбор пока не подключён. Даты и турниры в демо взяты из опубликованного календаря Ассоциации гольфа России на 2026 год; перед публичным запуском нужно повторно проверить их статус у организатора.

## Запуск мобильного прототипа
Нужны Node.js LTS и npm:
```bash
cd mobile
npm install
npx expo start
```
Затем откройте QR-код в Expo Go на телефоне либо запустите симулятор.

## Запуск API-заготовки
Нужны Python 3.11+:
```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
Документация API: http://127.0.0.1:8000/docs

Сейчас API отдаёт демонстрационные данные из памяти процесса. Для production нужно подключить PostgreSQL, авторизацию, миграции, журналирование и обработку ошибок.

## Ежедневное обновление на сервере
Для реального режима нужны:
1. Облачный сервер/контейнер для API.
2. PostgreSQL с резервными копиями.
3. Планировщик (например, Celery + Redis, APScheduler либо облачный cron).
4. Коннекторы к разрешённым источникам: официальные API/RSS/страницы, на которых разрешён автоматический сбор.
5. Проверка новых и изменившихся событий, сохранение URL, даты проверки и фрагмента источника.
6. Отдельный слой проверки конфликтов: если даты или победители различаются, не перезаписывать автоматически без подтверждения первоисточником.
7. ИИ-публикации только на основе извлечённых фактов; каждое утверждение должно ссылаться на источник.
8. Мониторинг, повторные попытки, алерты и журнал неудачных обновлений.

## Рекомендуемые сущности
- Tournament: название, тип спорта (гольф/мини-гольф), начало/конец, страна, регион, площадка, уровень, статус, организатор, регистрация, регламент, источник.
- Result: турнир, участник/команда, место, счёт, раунды, статус подтверждения.
- Source: URL, тип источника, приоритет доверия, последний успешный сбор, статус.
- ChangeLog: поле, старое/новое значение, источник, время изменения.
- Article: текст, список источников, модель/версия, дата публикации, статус проверки.

## Источники для первичного подключения
- Ассоциация гольфа России — календарь 2026: https://rusgolf.ru/ru/contests/tournament-calendar
- Ассоциация гольфа России — соревнования 2026/2027: https://rusgolf.ru/ru/contests/sorevnovaniya-2026
- Белорусская ассоциация гольфа — календарный план 2026: https://ingolf.by/turniryi/kalendarnyij-plan-na-2026
- Казахстанская федерация гольфа: https://fedgolf.kz/ru
- UZGolf — турниры и результаты: https://uzgolf.uz/en/events-en/
- World Amateur Golf Ranking (дополнительный контекст рейтинга): https://www.wagr.com/

В API `/sources` теперь зарегистрированы шесть источников с полями страны, типа, назначением, уровнем доверия, статусом и заметками о проверке. `/sources/{source_id}` возвращает карточку конкретного источника. В мобильной вкладке «Источники» показаны те же шесть источников. Статус `configured_not_crawled` или `configured_manual_review` означает, что ссылка внесена в реестр, но ежедневный сбор ещё не работает. Казахстанские и узбекские страницы могут содержать старые сезоны, поэтому их нельзя считать подтверждением текущих дат без перепроверки.

Перед запуском автоматического сбора проверьте условия использования, robots.txt, доступность API/RSS и допустимость извлечения данных каждого сайта. Для результатов и победителей предпочтительны официальные протоколы организатора.

Необходимо проверить условия использования каждого источника и использовать официальный API/RSS, если он доступен.


## Version 4 — source monitoring
- `sources.json` contains the central source registry, including Moscow, St Petersburg, Moscow Oblast, Krasnodar Krai, Krasnoyarsk Krai and Astana.
- `backend/app/collectors/monitor.py` checks configured pages, records snapshots/hashes and queues changed pages for review.
- `backend/app/collectors/scheduler.py` runs the monitor every day at 06:00 Moscow time.
- This is source-change detection, not yet fully structured tournament extraction. Region entries that reuse a national calendar are explicitly marked as needing verified regional URLs.
